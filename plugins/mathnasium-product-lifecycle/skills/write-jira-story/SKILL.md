# Write Jira Stories

1. Read the live [Handbook Index](https://mathnasium.atlassian.net/wiki/spaces/IPD/pages/2162819145) through the Atlassian connector. Supported Plugin contract: 1. If the contract changes incompatibly, report that the plugin needs updating.
2. Follow the intent router to the current playbook, standard and template. Local reference files are pointers only; fetch their Confluence page bodies, not search snippets alone, before applying rules.
3. Fetch the relevant Jira issue, parent and comments live. Use GitHub for implementation evidence when needed.
4. Draft, review or refine within the user's requested scope and existing authorization. Preserve unresolved questions and proposed/TBC labels. Do not turn a draft rule into an enforced policy.
5. Refresh any page the user says changed. Reuse unchanged reads, but fetch fresh target state before writes and honor pagination when listing pages.

If Confluence cannot be read, report which required guidance is unavailable. Do not substitute historical Git policy or invent requirements. Do useful independent work without claiming the unavailable rule was checked.

Jira owns live tickets and commitments; Confluence owns durable rules; repositories own code and tooling. Do not copy secrets into artifacts or Jira. Link every Jira key in user-facing output.
